# AgentForge CI/CD Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Registar-style GitHub CI and release automation adapted to AgentForge.

**Architecture:** Keep AgentForge-specific quality and Docker integration commands local. Reuse the shared `LukaszRemkowicz/ci-cd` workflows for generic policy, security, PR reporting, and release tags.

**Tech Stack:** GitHub Actions, Python 3.12, uv, Ruff, Pyright basic, pytest, Docker Compose, pip-audit, Trivy, Dependabot.

**Spec:** `docs/superpowers/specs/2026-09-30-ci-cd-design.md`

## Global Constraints

- Use Registar as the structural reference but remove Registar-specific fixtures, package names, and Pyright ratchet.
- Run CI on pull requests and pushes to `main`/`dev`.
- Exercise real pgvector integration tests on hosted Linux Docker.
- CD means version tagging only; there is no package or runtime deployment target.
- Preserve Pyright basic mode and Python 3.12.
- Work only on `dev`; do not push without a separate explicit request.

## Review Focus

- YAML parses and reusable workflow inputs match their declared contracts.
- Integration cleanup runs even when tests fail.
- PR status handles skipped version checks without hiding failures.
- Release tagging reads the static version from `pyproject.toml`.
- Documentation moves do not lose the architecture plan or retain the superseded market evaluation.
